# 00 项目简介

## 1 项目背景

中医学有文字可考的历史超过两千年，从《黄帝内经》奠基到温病学派成熟，其间形成了庞大的人物谱系、经典文献、学术流派与诊疗体系。然而这些知识长期散落在古籍、论文与口述传承中，缺乏结构化、可检索、可交互的数字化载体。普通学习者面对浩如烟海的文献无从下手，专业研究者也难以快速厘清学派传承与概念演变。

近三年大语言模型（LLM）与检索增强生成（RAG）技术趋于成熟，知识图谱与向量检索的结合让"让机器读懂古籍并回答问题"成为现实。与此同时，国家层面对中医药文化传承与数字化的重视持续加码，2022 年《"十四五"中医药发展规划》明确提出推进中医药文化传承与信息化建设。技术成熟与政策推动共同构成了本项目的外部契机。

TCM-History-AI 正是在这一背景下立项。它不是又一个把古籍扫描成 PDF 的电子图书馆，而是以 AI 为核心引擎，将中医发展史重构为可问答、可关联、可学习的活态知识体系。

## 2 为什么做中医发展史

中医的价值不只在于方药与针灸，更在于其背后一脉相承的学术演进。理解"某位医家为何提出某个理论"，往往比记住方剂本身更重要。现有数字化产品普遍存在三个缺口：

第一，**重内容堆砌，轻结构关联**。多数产品把经典文献按章节罗列，却无法回答"张仲景的六经辨证如何影响了后世温病学派"这类关联性问题。

第二，**重静态阅读，轻交互学习**。用户被动翻阅文本，缺乏个性化学习路径与即时反馈，学完即忘。

第三，**重现代中医，轻历史脉络**。产品多聚焦当代方药与病症，对中医学术思想的历史演进着墨甚少，而这恰恰是中医文化传承的核心。

中医发展史是串联人物、经典、学派、事件的天然叙事载体，也是知识图谱技术最能发挥价值的领域。以"史"为线，把零散知识织成网络，再叠加 AI 问答与个性化学习，能够同时填补上述三个缺口。

## 3 市场分析

### 3.1 目标用户

| 用户群体 | 核心诉求 | 规模特征 |
| -------- | -------- | -------- |
| 中医院校学生 | 系统学习中医史、备考、查文献 | 国内 40+ 所中医药高校，在校生约 50 万 |
| 中医从业者 | 快速检索经典、追溯学术源流 | 执业医师约 87 万 |
| 中医爱好者 | 通俗了解中医文化、入门学习 | 泛兴趣人群千万级 |
| 中医药研究者 | 文献关联分析、学派演变研究 | 高校与院所研究人员 |
| 中小学文化教育 | 中医文化进校园的素材与课件 | 政策驱动的增量市场 |

### 3.2 市场规模

中医药信息化市场近年保持双位数增长。据行业研究，2024 年中国中医药大健康产业规模已突破 4 万亿元，其中数字化与信息化占比逐年提升。中医文化教育与科普赛道虽属细分，但受益于"中医药文化进校园"政策与大众对传统文化的兴趣回暖，呈现明显增量。

教育与 AI 结合的赛道同样处于上升期。AI + 知识型学习的模式已在法律、医学考试等领域验证可行，中医发展史具备同等的内容深度与结构化潜力，是一个尚未被充分开发的垂直场景。

### 3.3 市场趋势

- **AI 原生学习**：用户不再满足于检索式查询，期望对话式、个性化的学习体验。
- **知识图谱可视化**：复杂关联关系通过图谱呈现，比线性文本更易理解。
- **多端协同**：PC 深度学习、移动端碎片化学习、数据互通。
- **开放能力**：通过 API 与 MCP 将中医知识能力输出给第三方应用与 AI 助手。

## 4 产品定位

> **AI 驱动的中医发展史知识图谱平台。**

TCM-History-AI 以中医发展史为主线，将人物、经典、学派、朝代、事件、方剂、药物、疾病构建为一体化知识图谱，叠加 RAG 文献检索与 Agent 智能问答，为学习者提供从入门到研究的全链路学习体验。平台同时通过开放 API 与 MCP 协议，将中医知识能力输出给 Claude、GPT、Gemini 等主流 AI 助手。

核心差异化在于三点：以"史"为线的知识图谱结构、AI 原生的交互学习方式、开放的知识能力输出。

### 5.2 竞品评述

**中医智库**与**中医宝典**偏向临床工具，面向执业医师的方药检索需求，内容以现代方剂与病症为主，对中医学术史几乎没有覆盖，且完全不具备 AI 能力。

**中医百科**以词条形式组织内容，适合快速查询单个概念，但词条之间缺乏结构化关联，无法回答跨人物、跨学派的关联问题。

**黄帝内经 App**专注于单一经典的逐章阅读与白话翻译，适合入门精读，但覆盖面窄，且为静态阅读产品。

**中医在线**以录播课程为主，模式接近传统在线教育，缺乏个性化与即时交互，无法根据学习者水平动态调整。

上述产品共同的短板在于：内容静态、知识扁平、无 AI 交互、无开放能力。TCM-History-AI 的知识图谱结构、Agent 问答与 MCP 开放协议，在当前赛道中尚无直接对标者。

## 6 项目优势

### 6.1 知识图谱驱动

将中医发展史的八大类实体（人物、经典、学派、方剂、药物、疾病、朝代、历史事件）与九种关系（著作、师承、影响、属于、发生于、引用、提出、反对、继承）建模为 Neo4j 图谱，使任意两个知识点之间的关联路径都可被查询与可视化。这是线性文本与扁平检索无法实现的能力。

### 6.2 RAG 检索增强

对《黄帝内经》《伤寒论》《金匮要略》《针灸甲乙经》《温病条辨》《本草纲目》等核心经典做结构化处理与向量化，用户提问时先检索相关原文片段，再由 LLM 基于检索结果生成回答，从源头降低幻觉风险，使 AI 回答可溯源到具体古籍。

### 6.3 Agent 智能问答

采用 Planner→Reasoner→Retriever→Knowledge Graph→Memory→Reflection→Answer 的完整 Agent 链路，支持多轮对话、意图理解、知识图谱查询与反思修正。相比单轮 RAG 问答，Agent 能够处理需要多步推理的复杂问题。

### 6.4 开放能力输出

通过 MCP 协议将 TimelineTool、PersonTool、SchoolTool、ClassicTool、GraphTool、SearchTool、MedicineTool、PrescriptionTool 等能力封装为标准 Tool，Claude、GPT、Gemini 等主流 AI 助手均可调用，使平台成为中医知识的开放基础设施，而非封闭应用。

### 6.5 全栈工程化

从 Clean Architecture + DDD 的后端架构，到 40+ 张数据库表、200+ REST 接口、Docker 一键部署、Kubernetes 生产编排、CI/CD 自动化流水线，整套设计达到企业级工程标准，可直接进入开发阶段。
